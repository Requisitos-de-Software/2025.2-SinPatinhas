# Inspeção - Grupo 2 - Entrega 4

A 4ª inspeção do Grupo 2 da disciplina de Requisitos de Software foi realizada no dia 22/10, conduzida por Heloísa. O objetivo foi avaliar o processo de modelagem ágil dos requisitos do projeto, verificando a conformidade com os critérios estabelecidos pela disciplina.

## Lista de Verificação - Modelagem Ágil de Requisitos

| ID | Item de Verificação | Conforme? |
|----|---------------------|-----------|
| 1 | As Histórias de Usuário estão completas? | Sim |
| 2 | O "quem", "o que" e o "por que" estão definidos na história de usuário? | Sim |
| 3 | Há validação das histórias de usuário de modo presencial com o usuário? | Sim |
| 4 | Há gravação da validação das histórias de usuário? | Sim |
| 5 | Cada história possui critérios de aceitação? | Sim |
| 6 | Há validação dos critérios de aceitação das histórias de usuário de modo presencial com o usuário? | Sim |
| 7 | Há gravação da validação dos critérios de aceitação das histórias de usuário? | Sim |
| 8 | Há referência bibliográfica do modelo/estrutura das Histórias de Usuário? | Sim |
| 9 | As Histórias de Usuário são rastreáveis a sua origem? | Sim |
| 10 | Possui o cartão de especificação do RNF? | Sim |
| 11 | Os softgoals condizem com o contexto? | Não |
| 12 | Os impactos foram corretamente propagados? | Sim |
| 13 | Possui um tópico de agradecimento informando o uso de Inteligência Artificial (IA) Generativa no documento dos Léxicos? | Sim |

## Lista de Verificação - Histórias de Usuário

<font><p style="text-align: center">**Tabela 1** - Lista de verificação para o artefato histórias de usuário.</p></font>

| ID | Item de Verificação | Conforme? |
|----|---------------------|-----------|
| 1 | As histórias de usuário são pequenas, detalhadas e específicas? | Sim |
| 2 | As histórias de usuário começam explicitando qual o perfil de usuário interessado naquela história? (Como usuário X...) | Sim |
| 3 | As histórias de usuário possuem o que o usuário deseja daquele item? (Desejo Z funcionalidade) | Sim |
| 4 | Há em cada história de usuário a finalidade da funcionalidade desejada? (Desejo Z funcionalidade para Y finalidade) | Sim |
| 5 | A história é compreensível na perspectiva dos clientes? | Sim |
| 6 | A história evita detalhar o passo a passo ou as regras de negócio? | Sim |
| 7 | Cada história está devidamente relacionada a uma funcionalidade registrada no Product Backlog? | Sim |
| 8 | Cada história possui critérios de aceitação claros, objetivos e verificáveis? | Sim |
